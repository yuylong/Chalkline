# Chalkline 概念速查

供 Agent 判断「用户这句话对应哪个工具」，不替代 [docs/domain/model.md](../../../docs/domain/model.md)。

## 层级

```
产品（隔离单位，成员才能看见）
 └── 迭代（一条完整生命周期：调研 → 规划 → 拆解 → 研发 → 测评 → 发布 → 总结）
      └── 任务（多级树，最多 3 层，唯一负责人，跑自己的任务流）
```

- **迭代**承载生命周期；产品只是迭代的序列，本身不跑流程。
- **模块**是任务的分类标签（多对多），不是容器；一个任务可跨多个模块。

## 节点与状态

`pending` → `ready` → `in_progress` → `awaiting_review` → `passed`（或 `rejected` 回到 in_progress）

- `ready` 才能开始；开始用 `start_step`，提交用 `submit_step`。
- 无门禁的节点提交即通过；有门禁的节点提交后进入等待评审。

## 材料

`kind` + `provider` + `url`/`externalId`，例如 `{kind: "pr", provider: "git", url: "..."}`。没有外部工具时用 `inline` 附一段说明。**只挂引用，不贴正文。**

## 任务拆解

- 只有标记 `allows_task_creation` 的节点能建任务：默认「任务拆解」「研发」「测试设计」。
- 一级任务 `CHK-12`，二级 `CHK-12.3`，最多到三级；**不能跨迭代拆**，父子关系不可改。
- 拆解用 `chalkline_decompose_task` 批量创建，父任务负责人负责收口。
- 父任务终态要等所有子任务 `done`，叶子任务才是真正执行单元。

## 并行

- 工作流是 DAG：一个节点多条出边即并行，多前驱节点要**全部通过**才放行（AND 汇合）。
- 并行时 `get_next_action` 可能同时返回多个 `ready` 节点；先问用户做哪条，不替人选。
- 一条分支被驳回**不影响**其他分支；不要说「整个迭代卡住了」。
- 汇合点之前，缺少的那条分支会阻塞汇合节点，但不阻塞另一条分支的推进。

## 权限

- 只能看到自己加入的产品；非成员访问返回 `404`。
- 产品角色 `owner` / `member` / `guest`；`guest` 只读。
- 审批必须是门禁声明角色的持有者，且不能审批自己提交的节点。
