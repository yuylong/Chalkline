# 典型对话与调用序列

## 1. 日常推进

> **人**：CHK-12 现在到哪一步了？

```
chalkline_get_task(taskId: "CHK-12")
chalkline_get_next_action(taskId: "CHK-12")
```

> **Agent**：当前在「规格编写」，状态 `in_progress`。提交后需 1 名 reviewer 确认，材料要 1 份 `spec`。

---

## 2. 任务拆解

> **人**：帮我把 CHK-12 拆一下，前端做表单、后端做接口，再加一个前后端联调。

```
chalkline_get_task(taskId: "CHK-12")            # 确认存在、当前节点是否允许建任务
chalkline_decompose_task(
  parentId: "CHK-12",
  children: [
    { title: "任务表单前端", kind: "dev" },
    { title: "任务接口后端", kind: "dev" },
    { title: "前后端联调",   kind: "dev" }
  ]
)
```

> **Agent**：已拆成 3 个二级任务：CHK-12.1 表单前端、CHK-12.2 接口后端、CHK-12.3 前后端联调。要分别指派给谁？CHK-12 由你收口，子任务全部完成前它不能进入终态。

要点：

- **一次批量提交**，不要逐个调 `create_task`——编号连续、失败可整体回滚。
- 用户只说「拆一下」没给粒度时，**先问再拆**：拆成几个、按什么维度（前端/后端、模块、验收项）。
- 拆完必须问指派。**不要自动指派给当前用户**，那会让人以为任务已有人负责。

> **人**：联调那块太大了，再细分一下。

```
chalkline_decompose_task(
  parentId: "CHK-12.3",
  children: [
    { title: "联调环境准备", kind: "ops" },
    { title: "接口契约核对", kind: "dev" },
    { title: "端到端回归",  kind: "test" }
  ]
)
```

> **Agent**：CHK-12.3 下新增 3 个三级任务（CHK-12.3.1 ~ .3）。已经是第三层，再往下拆会触发 `TREE_DEPTH_EXCEEDED`，更细的工作建议写进任务描述。

> **人**：把 CHK-12.2 挪到下一个迭代。

> **Agent**：任务不能跨迭代拆解，也不能改父子关系。可以新建一个一级任务放到下一迭代，再关联原任务；要我这样建吗？

---

## 3. 并行工作流

> **人**：现在能同时做什么？

```
chalkline_get_next_action(iterationId: "CHK-IT5")
```

返回两个 `ready` 节点：`build`（研发）和 `test_design`（测试设计）。

> **Agent**：两条线可以并行：
> - 研发：可以建开发任务，推进实现；
> - 测试设计：可以建测试任务，先出测试计划。
>
> 两条都完成才会进入「测评」。先动哪条？如果 QA 已经能介入，建议先起测试设计——它通常比研发更容易提前卡住。

> **人**：测试设计先放着，把研发推完。

> **Agent**：好，只推进研发分支。测试设计保持 `ready` 不影响研发；但到「测评」汇合时仍然要求它通过，所以别忘掉。

要点：

- **并行时不要合并成一句话说「迭代进行中」**，要分别报两条线的状态。
- 用户选择一条线时，明确说明**另一条不会因此被跳过**，只是暂不推进。
- 不替用户决定顺序；可以给建议，但由人拍板。

> **人**：研发那块被驳回了，测试设计会受影响吗？

> **Agent**：不会。驳回只让研发节点回到 `in_progress`，测试设计继续照常评审；两边门禁互相独立。只有「测评」这个汇合点会等两条都 `passed`。

> **人**：那我现在能提交测评吗？

```
chalkline_get_next_action(iterationId: "CHK-IT5")
```

> **Agent**：还不能。测评要求前驱 `build` 与 `test_design` 都通过，现在 `build` 处于 `in_progress`（被驳回后重做），`test_design` 已 `passed`。阻塞点在研发。

---

## 4. 门禁被驳回

> **人**：规格评审没过，说范围写太大了。

```
chalkline_get_task(taskId: "CHK-12")
```

> **Agent**：驳回理由是「范围过大」，节点已回到 `in_progress`。修改后重新挂 `spec` 材料并再次提交即可——之前收集的 approve 继续有效，原驳回人重新确认后就能通过。要我把驳回意见整理成待办吗？

要点：**不要直接重提**。先确认用户是否已经改完材料——重提没改的内容只会再被驳回一次。

---

## 5. 权限不足

> **人**：帮我把 CHK-31 的状态改成完成。

```
chalkline_submit_step(...) → 403 ROLE_REQUIRED
```

> **Agent**：CHK-31 不是你负责的任务，你也没有 pm 角色，平台拒绝了这次操作（403 ROLE_REQUIRED）。需要由负责人或产品 owner 操作；我可以把要提交的材料清单整理给你转过去。

要点：**不重试、不换工具绕**。403 说明规则生效了，这正是平台的设计目的。
